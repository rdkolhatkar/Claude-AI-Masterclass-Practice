OUTLINE POINT 1: Use the Playwright MCP server
----------------------------------------------

Playwright MCP is an MCP server from Microsoft that lets an AI model drive a real browser through tools such as navigate, click, type text, fill form, take screenshot, and page snapshot.

- Project: https://github.com/microsoft/playwright-mcp
- Screenshot 01 shows the project's README, the "Getting started" section, and the standard JSON config.

OUTLINE POINT 2: Source and reference
------------------------------------

- Maintainer: Microsoft.
- Always confirm the current install command in the README before you copy it, because package names and arguments change.

OUTLINE POINT 3: Provide the MCP configuration in JSON
------------------------------------------------------

Claude reads its MCP servers from a JSON config file. Copy the standard config from the README (screenshot 01) into that file.

{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

Where to put it (Claude Desktop on Windows):

1. Open Claude Desktop and go to File > Settings (screenshots 02, 03).
2. Choose Developer under "This computer", then click Edit config (screenshot 04).
3. This opens claude_desktop_config.json. On this machine it is at C:\Users\Ratnakar\AppData\Local\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude (the Store-app location shown in screenshot 05). Open it with Notepad (screenshot 06).
4. Add the "playwright" block under "mcpServers" (screenshot 07). Keep the other keys in the file as they are.
5. Save the file and restart Claude Desktop.

OUTLINE POINT 4: Claude starts the MCP server locally
-----------------------------------------------------

- Claude Desktop runs the command from the config (npx @playwright/mcp@latest) on your machine. npx downloads the package the first time.
- Go back to Settings > Developer. The server appears under "Local MCP servers" with the status Running and a "View logs" button (screenshot 08). If it does not show Running, open the logs first.
- No browser is opened at this stage. The browser starts when Claude first calls a Playwright tool.

OUTLINE POINT 5: Give a plain-English prompt
--------------------------------------------

Once the server is running, you enable it in the chat and type a normal sentence.

1. In a new session, click + > Connectors and turn on "playwright" (screenshot 09). Use "Manage connectors" (screenshot 10) if you need to change it.
2. In Connectors, the playwright entry is listed as "Desktop - Local dev" with a check mark (screenshot 11).
3. Type the instruction in plain English (screenshot 13):

   Navigate to the "https://rahulshettyacademy.com/client" and click on the "Don't have an account? Register here" link

4. Claude decides which MCP tools to call, runs them, and reports back. In screenshot 14_A the answer says it used 4 tools, opened the page, clicked "Register here", and stopped on /client/#/auth/register without filling in or submitting the form. That stopping point is intentional in the prompt.

OUTLINE POINT 6: The server exposes tools, and you specify which ones to use
-----------------------------------------------------------------------------

Playwright MCP publishes its tool list to Claude. In Settings > Connectors > playwright you can see them (screenshots 12_A, 12_B):

  Group                 Count  Examples                                                                              Default permission
  --------------------  -----  ------------------------------------------------------------------------------------  ------------------
  Read-only tools          7   Page snapshot, Take a screenshot, Get console messages, List network requests,        Needs approval
                               Wait for
  Write/delete tools      18   Navigate to a URL, Click, Type text, Fill form, Press a key, Upload files,            Needs approval
                               Evaluate JavaScript, Close browser

For each tool, you can pick one of three icons per row: allow (check mark), needs approval (hand, the current setting in the screenshots), or block (circle with a slash). Set the tools your test needs to allow, and keep "needs approval" for anything that changes data. For the registration test above, Navigate to a URL, Click, and Page snapshot are the tools that matter.
